# pantheon-adr

Rust command line tool (`adr`) that creates, lists, checks and indexes Architecture Decision Records, plus the
bundled `adr-creator` agent skill. See `README.md` for what it does and how it is installed.

## Layout

- `crates/adr/`: the only workspace member. `src/lib.rs` documents each module; `tests/integration.rs` holds the
  integration tests; `docs/design/` holds the design notes.
- `skills/adr-creator/`: the skill (`SKILL.md`, `references/`, `evals/`, and `assets/`, which holds the record
  template `assets/adr.yaml` and the frontmatter schema `assets/adr-frontmatter.schema.json`). `build.rs`
  embeds it in the binary, so a change here changes the binary.
- `.github/workflows/`: CI. `rust-ci.yml` is the source of truth for what must pass.
- `.context/`: gitignored working state. Never commit it.

## Commands

Tools are pinned in `mise.toml` (`mise install` sets them up and installs the git hooks).

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --workspace --locked
cargo test --workspace --locked
mise run lint        # markdown, via rumdl
mise run check       # every hk check, the same steps as the git hooks
```

Run `cargo` with `--locked`: CI does. When checking test results, require `0 failed` on every suite; do not add up
the "passed" counts.

## Conventions

- Branch off `main`, never commit to it. Conventional commits with a scope, for example `fix(cli): reject an empty
  title`; the squash-merge subject ends in the PR number.
- PR bodies use the three headings in `.github/pull_request_template.md`: What, Why, Notes.
- A PR title is `type(scope): lowercase summary`, checked by the Conventional Commit Title workflow. PRs are
  squash-merged, so the title is the commit message release-please reads. The allowed types are release-please's
  defaults, listed in `.github/commit-types.txt`; the title workflow holds a copy in its regex, and
  `.github/scripts/check-commit-types.sh` fails if the two drift.
- Git hooks run through `hk` (`hk.pkl`): rustfmt, rumdl, yamllint, shellcheck and actionlint on commit; clippy and
  tests on push. Do not skip them.
- `.github/workflows/release.yml` is generated by cargo-dist: never edit it by hand. Its known zizmor and actionlint
  findings are listed in `.github/zizmor.yml` (matched by line and column) and `.github/actionlint.yaml`. After
  `dist generate`, re-run both linters and update the line numbers if they moved.
- Markdown is linted by rumdl with `.rumdl.toml`. Shell scripts must pass shellcheck.
- The Rust toolchain version is set in `rust-toolchain.toml` (the source of truth), `mise.toml`, `rust-ci.yml` and
  `cargo-deny.yml`, with `rust-version` in `Cargo.toml` as its major.minor. Change them together:
  `.github/scripts/check-toolchain-version.sh` runs in `rust-ci.yml` and fails if they differ.
- The `pahdk-*` dependencies are pinned in the root `Cargo.toml`, to a git tag. Both crates must share one pin.
- State is stored under `$XDG_DATA_HOME/tekhne/adr` (or `~/.local/share/tekhne/adr`). Keep that path.
- Behaviour is a pure function of on-disk content plus an injectable "today", so tests need no clock.
